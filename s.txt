## Even Cleaner: Default Tool Validation

```typescript
function validateTools(ir: AgentIR, tools: Record<string, Function>) {
    const required = ir.tools.map(t => t.name);
    const provided = Object.keys(tools);
    const missing = required.filter(r => !provided.includes(r));
    
    if (missing.length > 0) {
        throw new Error(
            `School agent is missing required tools:\n` +
            missing.map(m => `  - ${m}`).join('\n') +
            `\n\nExpected tools based on school.agent DSL:\n` +
            ir.tools.map(t => `  - ${t.name}: ${t.description}`).join('\n')
        );
    }
}
```

## The Trade-offs

| Approach | Pros | Cons |
|----------|------|------|
| **Embedded JSON** | Self-contained file | Large bundle, slow TS, git noise |
| **JSON Import** | Clean separation, smaller TS files | Requires `resolveJsonModule`, JSON file must exist at runtime |

## Handling the JSON Import Properly

### 1. **Ensure `tsconfig.json` has:**
```json
{
  "compilerOptions": {
    "resolveJsonModule": true,
    "esModuleInterop": true
  }
}
```

### 2. **Generate Side-by-Side Files:**
```
output/
├── school.agent.types.ts  # Generated types + factory
├── school.agent.json      # IR (referenced by .types.ts)
└── school.agent.js        # Compiled JS (bundler handles JSON)
```

### 3. **Alternative: Dynamic Import (for huge IRs)**
```typescript
export async function createSchool(config: { ... }) {
    // Lazy load IR only when needed
    const { default: ir } = await import('./school.agent.json', {
        assert: { type: 'json' }
    });
    
    const agent = new Agent(...);
    agent.load(ir as AgentIR);
    return agent;
}

// Usage:
const agent = await createSchool({ tools });
await agent.run(input);
```

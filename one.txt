Design Decision: #[quew_builtin] Proc-Macro
Scope: Compiler-prelude native bindings only.
Status: Proposed — builds on completed Plans 11 (native leaves) and 12 (extension methods).
Excludes: Host-developer tool macros (#[quew_host_tool], #[quew_plugin], etc.) which belong to a separate runtime-extensibility RFC.
1. Problem
Plan 11 introduced @@rust("id") so builtin functions can declare a stable native implementation ID:
quew
Copy
@@rust("std.string.is_empty")
!@@function string_is_empty(value: string): bool
Plan 12 added extend Type { ... } so users can call methods like "hello".isEmpty().
The remaining friction is manual duplication:
A Rust implementer writes the function body in crates/quew-stdlib/src/string.rs.
The same person manually writes the Quew prelude declaration in prelude/native.quew.
The same person manually writes the extend string { ... } wrapper in prelude/methods.quew.
The runtime registry is updated in a third file.
This is error-prone and slows stdlib iteration. The #[quew_builtin] proc-macro collapses these four artifacts into a single Rust source annotation.
2. Core Design
One attribute per native leaf. Three artifacts generated automatically:
Table
Artifact	Generated by	Consumed by
Quew prelude declaration	decl string + auto-wrap	Compiler (prelude/native.quew)
Runtime native dispatch entry	Function signature reflection	NativeRegistry at link time
Extension method wrapper (optional)	extend + method keys	Compiler (prelude/methods.quew)
The Rust function is the single source of truth. The Quew surface is derived from it.
3. Syntax
rust
Copy
// crates/quew-stdlib/src/string.rs
use quew_macros::quew_builtin;

#[quew_builtin(
    id    = "std.string.is_empty",
    decl  = r#"!@@function string_is_empty(value: string): bool"#,
    extend = "string",
    method = "isEmpty"
)]
pub fn string_is_empty(value: &str) -> bool {
    value.is_empty()
}
Field semantics:
Table
Field	Required	Purpose
id	Yes	Stable native dispatch key referenced by @@rust("...")
decl	Yes	Raw Quew declaration emitted into the prelude
extend	No	Receiver type for auto-generated extension method
method	No	Method name exposed to Quew callers
Rules:
extend and method must appear together or not at all.
The macro does not parse or validate the Quew syntax in decl. It is emitted verbatim; the Quew compiler validates it during its own parse phase.
The Rust function signature must be compatible with the decl contract (enforced by convention and tests, not by the macro).
4. Generated Artifacts
4.1 Prelude declaration (auto-generated)
From the example above the build pipeline emits:
quew
Copy
@@rust("std.string.is_empty")
!@@function string_is_empty(value: string): bool

extend string {
    function isEmpty(): bool {
        return string_is_empty(self)
    }
}
This lands in prelude/native.quew (or prelude/methods.quew depending on build-script partitioning). It is a build artifact — never edited by hand.
4.2 Runtime dispatch entry
The macro generates a registration fragment using the inventory crate (or an equivalent link-section collector):
rust
Copy
#[doc(hidden)]
mod __quew_builtin_string_is_empty {
    use super::*;
    use quew_runtime::{NativeRegistry, NativeEntry, NativeHandler, Value};

    inventory::submit! {
        NativeEntry {
            id: "std.string.is_empty",
            arity: 1,
            handler: NativeHandler::Sync(|args| {
                let s = args[0].as_str()
                    .ok_or_else(|| NativeError::type_mismatch("string", args[0].type_name()))?;
                Ok(Value::Bool(string_is_empty(s)))
            }),
        }
    }
}
At server startup the runtime iterates the collected inventory and populates NativeRegistry::entries: HashMap<&'static str, NativeEntry>.
4.3 Async variant
Native functions that suspend (e.g., I/O) declare async in Rust and set r#async = true in the attribute:
rust
Copy
#[quew_builtin(
    id       = "std.fetch",
    decl     = r#"!@@function fetch(url: string): ToolResult<string>"#,
    r#async  = true
)]
pub async fn fetch(url: &str) -> Result<String, reqwest::Error> {
    reqwest::get(url).await?.text().await
}
The generated handler becomes:
rust
Copy
NativeHandler::Async(|args| {
    let url = args[0].as_str()?;
    Box::pin(async move {
        let result = fetch(url).await?;
        Ok(Value::String(result))
    })
})
The graph executor detects NativeHandler::Async, suspends the current node, and polls the future through the runtime's async bridge.
5. Build Pipeline
Text
Copy
Rust source files in crates/quew-stdlib/src/
    │
    ▼
#[quew_builtin(...)] attributes
    │
    ├──► proc-macro expands ──► inventory entries (link-time)
    │
    └──► build.rs in quew-prelude crate
            │
            ├──► scans link sections / inventory
            ├──► concatenates all `decl` strings
            ├──► auto-wraps extension methods
            └──► writes prelude/native.quew
                        │
                        ▼
            quew-compiler loads prelude/native.quew
            at startup via include_str! or file path
The prelude file is rebuilt whenever quew-stdlib changes. In CI the build script fails if the generated prelude drifts from committed state, ensuring the checked-in prelude/ stays in sync.
6. Trust Boundary
#[quew_builtin] is prelude-only. The compiler must reject @@rust in user source.
Table
Layer	Can use #[quew_builtin]?	Can write @@rust in .quew?
quew-stdlib / compiler team	Yes	Yes (generated)
Host developer (server builder)	No	No
Agent author (end user)	No	No
This preserves the sandbox: user Quew code cannot inject arbitrary native Rust execution. Only the compiler-owned standard library carries native binding IDs.
7. Relationship to Existing Plans
Table
Plan	What it added	How the macro uses it
Plan 11	@@rust("id") metadata on builtin functions	The macro generates the @@rust prefix automatically from the id field
Plan 12	extend Type { ... } and implicit self	The macro generates the extend block and the self argument wiring
Plan 10	Builtin function declarations (@@function)	The decl string carries the @@function or !@@function signature
Plan 7–9	Role bindings, prelude loader, ToolResult<T>	The generated prelude participates in the same loader pipeline as hand-written .quew files
No parser, checker, or IR changes are required. The macro feeds the existing pipeline with auto-generated text.
8. Open Questions
Signature inference: Should a future revision derive the decl string from the Rust function signature (&str → string, bool → bool) instead of requiring an explicit decl string? This reduces duplication but adds complexity when Rust types do not map 1:1 to Quew types.
Monomorphization: If a builtin is generic in Rust (fn foo<T>(x: T)), how is the Quew generic parameter represented? Deferred until Quew generics are exercised in native contexts.
Error mapping: Should the macro auto-generate NativeError conversion from the Rust function's Result type, or is manual wrapper code preferred for fine-grained diagnostics?
Module partitioning: Should extension methods be emitted into prelude/methods.quew or co-located with their native declarations in prelude/native.quew?
9. Summary
#[quew_builtin] lets the language author write one Rust function and receive:
a Quew prelude declaration,
a runtime native dispatch entry,
and optionally an extension method wrapper,
all generated at build time. It does not change the compiler's trust model (@@rust remains prelude-only) and it does not introduce new syntax beyond the existing @@rust, @@function, and extend constructs from Plans 11 and 12.
The artifact is a build convenience for the stdlib author, not an end-user extension mechanism.

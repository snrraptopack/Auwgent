# Changelog - January 29, 2026

## IR Runtime Fixes

### Overview
Resolved prompt and workflow evaluation mismatches between generated IR and the JavaScript loader runtime.

### Changes
- Template IR now uses `value` to match the runtime evaluator.
- Added `concat` expression support in the evaluator and IR types.
- Context is injected as `ctx` for prompt and workflow scopes.
- Prompt scope now includes the full `input` object for `input.*` references.

## Added

### Cross-File Referencing System
- **Cross-file referencing** for modular agent development
- Import statements with optional kind annotations: `import { helper DataFetcher, type User } from "./helpers"`
- Export keyword for helpers, types, and prompts
- Named imports with optional aliases: `import { User as UserType } from "./types"`
- URI resolver for relative path resolution with automatic `.agent` extension
- Import cache manager for performance optimization
- Scope computation service to collect and publish exported symbols
- Enhanced scope provider to resolve imported symbols across files
- Comprehensive validation:
  - Import path resolution validation
  - Symbol existence and export status validation
  - Import kind validation (ensures `helper` imports are actually helpers)
  - Circular dependency detection with full cycle path reporting
  - Export dependency warnings for incomplete public APIs
- Transitive dependency support (non-exported elements used by exported ones)
- Autocomplete support for import paths and imported symbols

### DX Improvements
- **Direct output type usage**: `output: User @desc "..."` flattens type properties without nesting
- **Multi-line string templates**: `"""..."""` with `{{expression}}` interpolation support
- Multi-line strings preserve newlines and whitespace
- Interpolation supports context properties: `{{ctx.userName}}`, `{{ctx.user.email}}`
- Nested property access in interpolation: `{{ctx.user.name}}`
- Prompt concatenation with multi-line strings: `PromptRef + """...""" + PromptRef`
- Conditionals with multi-line strings in prompt blocks using `return`

### Workflow & Tools
- Workflow-scoped tools in DSL grammar and runtime
- TypeScript types generation includes workflow tools for IntelliSense
- Validation prevents inline prompt blocks in return statements
- Support for optional commas in object type property lists

- WorkflowRunner and ExpressionEvaluator respect scoped tool definitions

## Example Usage

### Cross-File Referencing
```auwgent
// helpers.agent
export type User {
    name: string
    email: string
}

export helper DataFetcher {
    description: "Fetches data"
    input { url: string }
    output { data: string }
}

// main.agent
import { DataFetcher, User } from "./helpers"

agent MainAgent {
    input { user: User }
    helpers { DataFetcher }
}
```

### Direct Output Types
```auwgent
type User {
    name: string
    email: string
}

agent MyAgent {
    output: User @desc "User information"  // Flattens to { name, email }
}
```

### Multi-line String Templates
```auwgent
agent MyAgent {
    default config {
        model: openai("gpt-4")
        prompt: """
Hello {{ctx.userName}}!

Your email is: {{ctx.userEmail}}
"""
    }
    
    context {
        userName: string
        userEmail: string
    }
}
```

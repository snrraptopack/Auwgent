## Enhanced Type System Implementation

Completed a comprehensive enhancement to the type system, enabling full support for complex types including type references, nested objects, arrays, unions, and inline object types. ## DX Improvements - Unified Configuration Pattern

### Overview
Implemented unified configuration pattern to eliminate two-phase initialization and per-call config passing, making the API feel like a proper SDK.

### Changes

#### 1. Unified Configuration Interface
**Before:**
```typescript
const agent = createTypeSystemTest({ geminiApiKey: '...' });

await agent.run(input, tools, context, lifecycle, configName);  // Config per-call
```

**After:**
```typescript

    apiKeys: { geminiApiKey: '...' },

    context: { sessionId: "10" },  // Bound once
```


Config can still be overridden per-call:

## DSL Grammar Changes

### File: `packages/language/src/auwgent.langium`

#### 1. Fixed Array Type Syntax
**Problem**: Array syntax only supported primitives, not objects or type references.

**Solution**: Used left recursion with infer action:
```langium
Types:
    BaseType ('[' ']' {infer ArrayType.elementType=current})*;
```

This allows:
- `Point[]` - Array of type references
- `string[]` - Array of primitives  
- `{ title: string, url: string }[]` - Array of inline objects

#### 2. Removed Comma Requirements in ObjectType
**Problem**: `ObjectType` required commas between properties, but `TypeDeclaration` didn't, causing inconsistency.

**Solution**: Made commas optional in `ObjectType`:
```langium
ObjectType:
    '{' (properties+=ObjectProperty)* '}';
```

#### 3. Added UnionType to BaseType
**Problem**: Union types weren't recognized in all contexts.

**Solution**: Added `UnionType` to `BaseType` alternatives:
```langium
BaseType:
    type=(StringType | NumberType | BooleanType | ObjectType | UnionType)
    | typeRef=[TypeDeclaration:ID];
```

#### 4. Made Output @desc Optional
**Problem**: Both `Output` and `TypeConfigDeclaration` had `@desc`, causing parser ambiguity.

**Solution**: Made `@desc` optional on `Output`:
```langium
Output:
    td=TypeConfigDeclaration (description=Description)?;
```

##### 2. IRType Union
Represents all possible type structures:
```typescript
export type IRType =
    | string                    // Primitives: "string", "number", "boolean"
    | ArrayTypeIR               // { type: "array", items: IRType }
    | TypeRefIR                 // { type: "typeRef", name: "TypeName" }
    | UnionTypeIR               // { type: "union", options: [...] }
    | ObjectTypeIR;             // { type: "object", properties: {...} }
```

##### 3. Specific Type Interfaces
```typescript
export interface ArrayTypeIR {
    type: "array";
    items: IRType;
}

export interface TypeRefIR {
    type: "typeRef";
    name: string;
}

export interface UnionTypeIR {
    type: "union";
    options: string[];
}

export interface ObjectTypeIR {
    type: "object";
    properties: Record<string, IRType>;
}
```

##### 4. Type Definition Structure
```typescript
export interface TypeDefinition {
    isOutput: boolean;
    properties: Record<string, PropertyInfo>;
}

export interface PropertyInfo {
    type: IRType;
    optional: boolean;
    description?: string;
}
```

```typescript
    // Case 1: Primitive strings
    if (typeof irType === 'string') { ... }

    if (irType.type === 'array') { ... }
    
    // Case 3: Type references - RESOLVE RECURSIVELY
    if (irType.type === 'typeRef') {

    }
    
    // Case 4: Union types

    // Case 5: Inline object types

```

#### 3. NEW: typeDefToSchema()
Resolves type references recursively:
```typescript
private typeDefToSchema(typeName: string): JsonSchema {
    const typeDef = this.ir.types[typeName];
    const properties: Record<string, JsonSchema> = {};
    const required: string[] = [];

    for (const [propName, propInfo] of Object.entries(typeDef.properties)) {
        // Recursively convert property type
        properties[propName] = this.convertTypeToSchema(propInfo.type);
        
        if (propInfo.description) {
            properties[propName].description = propInfo.description;
        }
        
        if (!propInfo.optional) {
            required.push(propName);
        }
    }

    return { type: "object", properties, required };
}
```

## Comprehensive Error Handling Implementation

### Overview
Implemented comprehensive error handling across all runtime components to eliminate unhandled promise rejections and provide clear, actionable error messages to users.

### Changes

#### 1. New Error Type System
**File**: `javascript/loader/types/errors.ts` (NEW)

Created specialized error classes for different failure scenarios:

##### DriverError
Wraps all driver-level errors (network, API, authentication):
```typescript
export class DriverError extends Error {
    type: ErrorType;              // Classified error type
    originalError: Error;         // Original SDK error
    retryable: boolean;           // Can this be retried?
    statusCode?: number;          // HTTP status code
    
    getUserMessage(): string;     // User-friendly message
}
```

**Error Types**:
- `AUTH_ERROR` - Invalid API key (not retryable)
- `RATE_LIMIT` - 429 Too Many Requests (retryable)
- `NETWORK_ERROR` - Connection failed (retryable)
- `INVALID_REQUEST` - 400 Bad Request (not retryable)
- `CONTENT_POLICY` - Content filtered (not retryable)
- `TOKEN_LIMIT` - Context window exceeded (not retryable)
- `MODEL_NOT_FOUND` - Invalid model name (not retryable)
- `UNKNOWN_ERROR` - Unclassified (not retryable)

##### LifecycleError
Wraps lifecycle hook failures:
```typescript
export class LifecycleError extends Error {
    hook: 'prune' | 'load' | 'save';
    originalError: Error;
}
```

##### WorkflowError
Wraps workflow execution failures:
```typescript
export class WorkflowError extends Error {
    workflowName: string;
    stepName?: string;
    originalError: Error;
}
```

##### StreamError
Wraps streaming failures:
```typescript
export class StreamError extends Error {
    phase: 'initialization' | 'streaming' | 'handler';
    originalError: Error;
}
```

##### ConfigurationError
Thrown for invalid agent configuration:
```typescript
export class ConfigurationError extends Error {
    // Clear message about what's wrong
}
```

##### SchemaValidationError
Thrown when model output doesn't match expected schema:
```typescript
export class SchemaValidationError extends Error {
    output: unknown;
    expectedSchema: Record<string, unknown>;
    validationErrors: string[];
}
```

1. **Catch specific error types**:
```typescript
try {
    await agent.run(input);
} catch (error) {
    if (error instanceof DriverError) {
        // Handle driver errors
    } else if (error instanceof LifecycleError) {
        // Handle lifecycle errors
    } else if (error instanceof WorkflowError) {
        // Handle workflow errors
    }
}
```

2. **Check if error is retryable**:
```typescript
catch (error) {
    if (error instanceof DriverError && error.retryable) {
        return retry();
    }
}
```

3. **Get user-friendly messages**:
```typescript
catch (error) {
    if (error instanceof DriverError) {
        console.error(error.getUserMessage());
    }
}
```

### Impact

This implementation:
- ✅ **Eliminates unhandled promise rejections**
- ✅ **Provides clear, actionable error messages**
- ✅ **Enables intelligent retry logic**
- ✅ **Preserves original errors for debugging**
- ✅ **Prevents single handler from crashing streams**
- ✅ **Adds context to workflow errors**
- ✅ **Makes lifecycle errors traceable**
- ✅ **Production-ready error handling**

The runtime now has comprehensive error handling across all components, making it production-ready and user-friendly.

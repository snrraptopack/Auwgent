# Changelog - January 27, 2026

## Enhanced Type System Implementation

### Overview
Completed a comprehensive enhancement to the type system, enabling full support for complex types including type references, nested objects, arrays, unions, and inline object types. The system now properly transforms DSL type definitions into JSON schemas for LLM structured output without using `any` types.

---

## DSL Grammar Changes

### File: `packages/language/src/auwgent.langium`

#### 1. Fixed Array Type Syntax
**Problem**: Array syntax only supported primitives, not objects or type references.

**Solution**: Used left recursion with infer action:
```langium
Types:
    BaseType ('[' ']' {infer ArrayType.elementType=current})*;
```

This allows:
- `Point[]` - Array of type references
- `string[]` - Array of primitives  
- `{ title: string, url: string }[]` - Array of inline objects

#### 2. Removed Comma Requirements in ObjectType
**Problem**: `ObjectType` required commas between properties, but `TypeDeclaration` didn't, causing inconsistency.

**Solution**: Made commas optional in `ObjectType`:
```langium
ObjectType:
    '{' (properties+=ObjectProperty)* '}';
```

#### 3. Added UnionType to BaseType
**Problem**: Union types weren't recognized in all contexts.

**Solution**: Added `UnionType` to `BaseType` alternatives:
```langium
BaseType:
    type=(StringType | NumberType | BooleanType | ObjectType | UnionType)
    | typeRef=[TypeDeclaration:ID];
```

#### 4. Made Output @desc Optional
**Problem**: Both `Output` and `TypeConfigDeclaration` had `@desc`, causing parser ambiguity.

**Solution**: Made `@desc` optional on `Output`:
```langium
Output:
    td=TypeConfigDeclaration (description=Description)?;
```

## IR Type System Changes

### File: `javascript/loader/types/ir.ts`

#### Removed All `any` Types
Replaced loose typing with proper TypeScript definitions for full type safety.

#### New Type Definitions

##### 1. TypeInfo Interface
Unified structure for all input/output/param fields:
```typescript
export interface TypeInfo {
    type: IRType;
    optional: boolean;
    description?: string;
}
```

##### 2. IRType Union
Represents all possible type structures:
```typescript
export type IRType =
    | string                    // Primitives: "string", "number", "boolean"
    | ArrayTypeIR               // { type: "array", items: IRType }
    | TypeRefIR                 // { type: "typeRef", name: "TypeName" }
    | UnionTypeIR               // { type: "union", options: [...] }
    | ObjectTypeIR;             // { type: "object", properties: {...} }
```

##### 3. Specific Type Interfaces
```typescript
export interface ArrayTypeIR {
    type: "array";
    items: IRType;
}

export interface TypeRefIR {
    type: "typeRef";
    name: string;
}

export interface UnionTypeIR {
    type: "union";
    options: string[];
}

export interface ObjectTypeIR {
    type: "object";
    properties: Record<string, IRType>;
}
```

##### 4. Type Definition Structure
```typescript
export interface TypeDefinition {
    isOutput: boolean;
    properties: Record<string, PropertyInfo>;
}

export interface PropertyInfo {
    type: IRType;
    optional: boolean;
    description?: string;
}
```

#### Updated Interfaces
- `AgentIR.input`: `Record<string, TypeInfo>` (was `Record<string, string>`)
- `AgentIR.output`: `Record<string, TypeInfo>` (was mixed types)
- `AgentIR.context`: `Record<string, TypeInfo>` (was `Record<string, string>`)
- `AgentIR.types`: `Record<string, TypeDefinition>` (NEW)
- `Tool.params`: `Record<string, TypeInfo>` (was `Record<string, string>`)
- `Tool.returns`: `IRType` (was `string`)
- `Workflow.flowParams`: `Record<string, TypeInfo>` (was `Record<string, string>`)
- `Workflow.returns`: `IRType` (was `string`)
- `HelperIR.input/output/context`: All use `TypeInfo` now

#### 2. Rewrote convertTypeToSchema()
Handles all IRType cases:
```typescript
private convertTypeToSchema(irType: any): JsonSchema {
    // Case 1: Primitive strings
    if (typeof irType === 'string') { ... }
    
    // Case 2: Array type objects
    if (irType.type === 'array') { ... }
    
    // Case 3: Type references - RESOLVE RECURSIVELY
    if (irType.type === 'typeRef') {
        return this.typeDefToSchema(irType.name);
    }
    
    // Case 4: Union types
    if (irType.type === 'union') { ... }
    
    // Case 5: Inline object types
    if (irType.type === 'object') { ... }
}
```

#### 3. NEW: typeDefToSchema()
Resolves type references recursively:
```typescript
private typeDefToSchema(typeName: string): JsonSchema {
    const typeDef = this.ir.types[typeName];
    const properties: Record<string, JsonSchema> = {};
    const required: string[] = [];

    for (const [propName, propInfo] of Object.entries(typeDef.properties)) {
        // Recursively convert property type
        properties[propName] = this.convertTypeToSchema(propInfo.type);
        
        if (propInfo.description) {
            properties[propName].description = propInfo.description;
        }
        
        if (!propInfo.optional) {
            required.push(propName);
        }
    }

    return { type: "object", properties, required };
}
```

#### 4. Updated paramsToSchema()
Simplified to work with `TypeInfo`:
```typescript
for (const [key, typeInfo] of Object.entries(params)) {
    properties[key] = this.convertTypeToSchema(typeInfo.type);
    if (!typeInfo.optional) {
        requiredFields.push(key);
    }
}
```

#### 5. Simplified objectTypeToSchema()
Now handles inline object properties:
```typescript
for (const [key, irType] of Object.entries(properties)) {
    schemaProps[key] = this.convertTypeToSchema(irType);
    required.push(key);
}
```

## Example Flow

### DSL Input
```
output type AnalysisResult {
    summary: string @desc "High-level summary of findings"
    confidence: number @desc "Confidence score between 0 and 1"
    keyFindings: string[] @desc "List of key findings"
}

agent TypeSystemTest {
    output {
        analysis: AnalysisResult @desc "The complete analysis"
    }
}
```

### Generated IR
```json
{
  "output": {
    "analysis": {
      "type": { "type": "typeRef", "name": "AnalysisResult" },
      "optional": false,
      "description": "The complete analysis"
    }
  },
  "types": {
    "AnalysisResult": {
      "isOutput": true,
      "properties": {
        "summary": {
          "type": "string",
          "optional": false,
          "description": "High-level summary of findings"
        },
        "confidence": {
          "type": "number",
          "optional": false,
          "description": "Confidence score between 0 and 1"
        },
        "keyFindings": {
          "type": { "type": "array", "items": "string" },
          "optional": false,
          "description": "List of key findings"
        }
      }
    }
  }
}
```

### Generated JSON Schema (sent to LLM)
```json
{
  "type": "object",
  "properties": {
    "analysis": {
      "type": "object",
      "description": "The complete analysis",
      "properties": {
        "summary": {
          "type": "string",
          "description": "High-level summary of findings"
        },
        "confidence": {
          "type": "number",
          "description": "Confidence score between 0 and 1"
        },
        "keyFindings": {
          "type": "array",
          "items": { "type": "string" },
          "description": "List of key findings"
        }
      },
      "required": ["summary", "confidence", "keyFindings"]
    }
  },
  "required": ["analysis"]
}
```

### LLM Response
```javascript
{
  analysis: {
    summary: "This is a placeholder for the summary of the data analysis.",
    confidence: 0.85,
    keyFindings: [
      "Key finding 1: ...",
      "Key finding 2: ...",
      "Key finding 3: ..."
    ]
  }
}
```

✅ **Perfect match!**

# Changelog - January 31, 2026

## Helper Handoff Re-architecture

### Overview
Moved helper handoff control into the helpers block so the main agent can decide user handoff behavior without wrapping helpers in workflows.

### Changes
- Helpers support `handoff user` and `handoff user then continue` directly in the helpers block.
- Handoff works alongside tool grants (`with tools{...}`) so helpers can run with explicit tool scopes.
- IR now carries helper handoff modes to the runtime.
- Runtime converts helper tool results into transfer signals for `user` and `user then continue`.
- Tool descriptions include handoff hints so the parent model can act correctly at the end of helper execution.
- Validation checks enforce valid handoff modes and warn on handoff helpers without tool grants.

### Files Modified
- packages/language/src/auwgent.langium
- packages/language/src/auwgent-validator.ts
- packages/language/src/generated/ast.ts
- packages/cli/src/generator.ts
- packages/cli/src/Types/typesGenerator.ts
- javascript/loader/types/ir.ts
- javascript/loader/Synthesizer.ts
- javascript/loader/IrInterpreter.ts

### Example Usage
```auwgent
agent Main {
    helpers {
        HelperA with tools{all} handoff user
        HelperB with tools{toolX} handoff user then continue
    }
}
```

## Model Imports + Standalone Models

### Overview
Added standalone model definitions and model references so configs can point to reusable, named models.

### Changes
- Model blocks allow named, reusable providers.
- Config `model` accepts a model reference in addition to inline providers.
- Cross-file imports can bring model definitions into another agent file.

### Example Usage
```auwgent
export model GeminiMain {
    provider: gemini("gemini-2.5-flash")
}

agent Main {
    default config {
        model: GeminiMain
        prompt: "..."
    }
}
```

## Core Runtime Middleware

### Overview
Middleware hooks provide a consistent lifecycle around model and tool execution for inspection, mutation, and retries.

### Changes
- Hook order covers agent start/end, model calls, tool calls, thinking, and errors.
- Priority-based ordering composes wrappers for model and tool execution.
- Middleware state is shared per run and can be seeded by the caller.

### Related Files
- javascript/loader/IrMiddleware.ts
- javascript/loader/types/protocol.ts
- javascript/loader/IrInterpreter.ts

## Generated Types

### Overview
Generated types now use `type` aliases to improve compatibility with unions and inferred types.

### Changes
- Generated Input, Output, Context, Tools, Lifecycle, and Config types emit as `type`.

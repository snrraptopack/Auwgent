The TypeScript FFI layer is completely broken for concurrent execution.

### The Concurrency Bug in the TypeScript FFI

In `auwgent.ts`, you manage the middleware context and event listeners as instance variables on the `TypedAuwgent` class:

```typescript
private sharedContext: Record<string, any> = {};
```

When someone calls `agent.run()`, you do this:
```typescript
async run(input?: string): Promise<SessionState> {
    this.sharedContext = {}; // Clear context for new run
    this.activateListeners();
    try {
        const json = await (native.run as any)(input ?? null, null);
        // ...
    } finally {
        this.deactivateListeners(); // Calls this.native.clearListeners()
    }
}
```

Because Node.js is asynchronous, if a user calls `agent.run()` twice concurrently on the same agent instance (e.g., handling two web requests at the same time), here is what happens:

1. **State Leakage**: Run A clears `sharedContext` and sets `ctx.user = "Alice"`. Moments later, before Run A finishes, Run B clears `sharedContext` and sets `ctx.user = "Bob"`. Run A will now start acting like Bob because `sharedContext` is a shared class-level variable, not scoped to the specific `run()` promise!
2. **Listener Destruction**: When Run A finishes, the `finally` block calls `this.deactivateListeners()`, which wipes the ThreadSafeFunctions on the Rust side. This instantly kills all intent callbacks and middleware events for Run B, which is still in the middle of executing. Run B will silently proceed without any middleware or intent handlers firing.

The Rust tests (`target rust or rustverification`) pass because Rust handles thread-safety and scoped state natively inside the engine loop. But your TypeScript `TypedAuwgent` wrapper acts like a singleton that assumes only one `run()` can ever happen at a time.

You were absolutely right to suspect the FFI layer is flawed. Fixing this will require scoping the `sharedContext` and the listener callbacks to a specific `run_id` across the FFI boundary, rather than storing them as class-level properties.
